## What’s awkward (from live cut)

1. **Two boards** — tiny mini-board above + full Guess grid = same scene twice; eats Chromebook height; question card cut off (~30% visible).
2. **Dense “Locked · …” stack** — three near-identical gray lines; hard to scan for mixed literacy / low-vis / ED.
3. **Tabs + chrome** — Guess / Watch / Find / Fix / Done + EN/ES/Big words/Home look tight; many hits likely under 44px.
4. **One answer visible** while the prompt asks what the bot does — layout implies more below fold; first-try fail for motor / scroll-averse kids.

Inclusion bar miss: D/HH and low-vis get no icon-first status; multilingual Big words exists but the board stack still forces scroll.

## One recommended option (do this)

**“One board · one prove card” layout (Chromebook-first)**

| Change | Why |
|--------|-----|
| **Kill the mini-board** on Guess (and any mode that already shows the main grid). Keep one play surface. | Subtract Before Add — frees ~80–120px; question stays above the fold. |
| **Collapse Locked stack → 3 icon chips** (Moved · On crate · One move) with short plain labels; Big words expands to full sentence. | Scan in one glance; icon+text (never meaning-by-color alone). |
| **No “Locked ·” prefix** (Curriculum) — clue text only. | Plain prove; less literacy load. |
| **Fat mode tabs ≥44×44**; max 4 visible + overflow “More” if needed. | Motor / Chromebook / ED calm targets. |
| **Prove card always docked under the one board** — question + answers fully on screen; no half-card. | First-try success for Solvay 7th / multilingual / ED. |
| **EN default; ES + Big words keep working** as chrome, not a second layout. | UDL in main defaults — no “special” Help ghetto. |

**Runner-up (only if Build refuses kill-mini):** auto-collapse mini-board when main grid is visible (same end state). Prefer kill.
